# Docs Workspace

## What This Workspace Is For
Hackathon rules, evaluation rubrics, award-specific strategy, and decision records.
Everything a teammate or the AI needs to understand *what we're optimizing for* before writing code.

## Process
1. Extract rules and metrics from official sources into standalone files.
2. Map each judging criterion to a concrete deliverable in the build.
3. Record decisions (idea selection, scope cuts, tech choices) with rationale.
4. Reference this workspace before any scope or priority change.

## Files In Here
- `rules.md` — Official hackathon rules distilled (times, submission requirements, constraints).
- `evaluation_metrics.md` — 100-point rubric + per-criterion strategy.
- `award_strategy.md` — What Thunders and NVIDIA Brev judges actually want, and how Jev maps to it.
- `karpathy_rules.md` — Karpathy coding guidelines applied to this build.
- `pitch_and_demo_notes.md` : Mentor session insights, defined metrics, storyboard, and submission copy.

## What Good Output Looks Like
A teammate can read `award_strategy.md` and know exactly which demo moment maps to which rubric criterion and which award, without opening the original onboarding page.

## Constraints
- No guessing. Every claim traces back to the official onboarding page or the PRD.
- Keep files under 1 page each. If it's longer, split it.
